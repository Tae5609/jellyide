## Priority (found by planner, 2026-11-22)
- [x] **DATA LOSS** `backend/internal/metadata/apply.go` (title rename) and `backend/internal/metadata/service.go` ApplyChanges: `os.Rename(track.Path, newPath)` with no existence check. On Linux `rename(2)` silently replaces an existing target, so renaming a track to a title that already exists in the album (or two titles that `sanitizeFilename` maps to the same name) **deletes the other audio file**. Same pattern in revert. → fixed by T17 — fixed in T17 (`fix(metadata): never overwrite existing files on track renames`, fsutil.SafeRename + auto-suffix)
- [x] `backend/internal/library/service.go` RenameAlbum: renaming onto an existing *empty* directory silently succeeds, and onto a non-empty one fails with a raw error. There is no explicit collision handling. → T17 — fixed in T17 (`fix(library): reject album rename onto existing folder`, 409 + ErrAlbumExists)
- [ ] Scanner never removes or marks rows for files that were deleted or moved outside JellyIDE: ghost rows, duplicates after external moves, and history attached to ghosts. → T16.
